# 数据边界约束（平台总控台）

> 本文档是**硬约束**，不是风格建议。违反第 3 节任意一条，改动一律不接受。

## 1 为什么要有这份文档

课堂分析天然涉及课堂视频、音频、师生对话、学生课堂行为与班级名册，其中很可能包含未成年人的个人信息。按《个人信息保护法》，视频、人脸、声纹属于敏感个人信息。

本平台的合规优势不是因为我们做了什么保护措施，而是因为**平台侧默认看不到这些内容**。这个优势一旦被一个「顺手加个链接」的操作破坏，补救成本远高于当初不加。

因此把边界写成可检查的规则，而不是留给下一个人凭直觉判断。

## 2 可见性边界

| 数据 | 教师本人 | 机构管理员 | 平台总控台 |
|---|---|---|---|
| 课例标题、课型、教师名、可见性、创建时间 | 自己的 | 本机构全部 | 全平台（仅元数据） |
| 报告总分、报告份数、生成时间 | 自己的 | 本机构全部 | 全平台（仅分数与计数） |
| 逐字稿 `transcript` / 观察记录 / 任务单文本 | 自己的 | 按可见性授权 | **禁止** |
| 课堂音视频原始文件 | 自己的 | 按可见性授权 | **禁止** |
| 标注内容（座位图、角色时间线、事件） | 自己的 | 按可见性授权 | **禁止** |
| 机构邀请码 | 仅本机构管理员 | 是 | 全平台可见 |

## 3 三条硬约束

1. **平台总控台不得出现课堂内容字段。**  
   `/api/admin` 及其子接口的任何响应里，不得包含 `transcript`、`observer_text`、`task_sheet_text`、`asset.file_url`、标注 payload、课堂对话文本。允许的字段只有元数据、统计量、质量指标。

2. **平台身份与机构身份必须独立判定。**  
   平台白名单判定只认 `platform_admins` 表（`lib/auth/platform-admin.ts` 的 `requirePlatformAdmin`），机构管理员身份（`org_members.role === 'admin'`）**不能**被用作任何平台视角的凭据，两者不得互相提权。

3. **跨租户聚合走 security definer 函数，不走高权限连接。**  
   平台侧所有聚合查询必须封装为 `security definer` 函数（`platform_*` 系列），函数体内校验白名单；应用层只调用函数，不得直接以高权限角色查询业务表。

## 4 要增加能力时的前置动作

如果需求是「平台侧需要能看到某节课的原始内容」，在动手写代码前必须同时完成：

1. 明确必要性说明与授权范围（法务确认，本文档不构成法律意见）
2. 该查看动作需要**额外权限**，不随 `platform_admins` 自动获得
3. 触发**二次鉴权**（重新输入凭据），不是复用当前会话
4. 写入审计日志，记录「谁、什么时间、查看了哪节课的哪类原始数据」

上述四项缺一，需求退回，不允许以「临时功能」「仅供排查」为由绕过。
