# 课堂分析报告 Word 导出 · 线上项目同步改造说明

> 适用对象：mathqingzhi.coze.site 现有项目的实现者。
> 性质：对现有项目的**增量改造**。不要重建项目，不要改评分逻辑，不要改报告数据结构。
> 目标：让线上项目与本地已验收的报告导出行为一致，并通过文末验收清单。

---

## 0. 改造边界

- 只改三处：**报告组件（导出按钮与请求）**、**导出路由（variant、自动补齐、传参、文件名）**、**docx 生成模块（两版内容与模板）**。
- 不改：五维评分算法、权重、档位判定、报告 `result` 字段结构、证据出处口径、页面现有展示与交互。
- 所有新增数据都来自现有报告对象、现有标注 payload、现有标准注册表；不要新增数据库字段或新表。

---

## 1. 页面两个导出入口

### 期望行为

报告页顶部保留两个 Word 导出按钮，文案与行为如下：

| 按钮文案 | 导出内容 | 请求方式 |
| --- | --- | --- |
| 下载精简版报告 | 精简版 `.docx` | 导出接口带 `variant=brief` |
| 下载完整版报告 | 完整版 `.docx` | 导出接口带 `variant=full` |

两者共用同一个导出接口、同一套样式与命名规则，只是内容口径不同。

### 交互细节

- 点击后按钮进入“生成中…”状态，两个按钮同时禁用，避免重复提交。
- 完整版发起请求前，页面提示：“若报告尚未生成 AI 解读，会先自动补齐，可能需要几十秒，请勿关闭页面。”
- 下载必须带登录态请求头，不能用普通 `<a href>` 直链。
- 服务端返回非 2xx 或 `Content-Type` 不是 `wordprocessingml` 时，按 JSON 读取错误并提示，**绝不能把错误 JSON 存成 `.docx`**。
- 401 时提示重新登录。
- 文件名优先取响应头 `Content-Disposition` 的 RFC 5987 中文名；取不到时用页面兜底名，并带“精简版/完整版”。
- 原“网页版下载”不再作为主导出入口；如保留，仅作移动端打印兜底，不占主按钮位。

### 验收标准

- 两个按钮文案准确，且分别下载到不同版本。
- 断网、401、服务端报错时页面有明确提示，不出现白屏或错误文件。
- 连续点击不会重复发起导出。

## 2. 精简版与完整版的内容口径

### 精简版（面向日常教研快速阅读）

按顺序包含：

1. **封面**：独立一页，含课例名、学校、班级、授课教师、报告生成人、评价标准、生成日期、报告版本、使用范围声明。
2. **一、一眼看这课（一页摘要）**
   - 一句话结论；
   - 先改这一处；
   - 综合分与等级；
   - 认知侧分数、情感侧分数、情智关系形态。
3. **二、五维评分**
   - 五维评分总表；
   - 逐维得分与等级；
   - 课型要点表（只保留要点表，不含逐点证据与观察点明细）。
4. **三、证据精选**：每个维度 2–3 条关键证据，保留出处与一句解读。
5. **四、课堂现场要点**：关键事件（最多 10 条）、座位布局、互动清单。
6. **报告性质声明与落款**。

精简版**不包含**：

- 57 个观察点明细；
- 四段 AI 解读（评分依据、为什么是这个分、如何解读、如何提升）；
- 附录 A、附录 B；
- 材料与数据覆盖表、AI 参与情况。

### 完整版（沿用第一版全量内容）

在精简版基础上补齐：

- 逐维二级指标表、理论依据、四段 AI 解读；
- 认知/情感 57 个观察点明细与逐点证据；
- 逐来源证据清单；
- 人工终裁留痕；
- 材料与数据覆盖表、AI 参与情况；
- 附录 A 评分档位说明、附录 B 理论依据与参考文献。

### 两版共同规则

- 同一套字体、字号、表格样式、表号规则、章节分页规则。
- 关键事件、座位布局、互动清单两版都保留。
- 文件名必须能区分“精简版/完整版”。

### 验收标准

- 精简版能在一页内读完摘要，且不含观察点明细与四段解读。
- 完整版包含第一版全部内容，不缺章、不缺表。
- 两版打开后目录结构、表号连续、样式一致。

## 3. 导出接口改造

### 3.1 variant 参数

- 查询参数：`variant=brief` 或 `variant=full`。
- 缺省按 `full` 处理，兼容旧链接。
- 精简版**不触发** AI 解读自动补齐，避免为不展示的内容付费。

### 3.2 完整版自动补齐 AI 解读

导出前检查报告对象：

- `dimension_interpretations`：按 `dimension_results` 里的维度 code 逐项比对，找出缺失维度。
- `essence_interpretations`：仅当 `essence_eval.llm_used` 为真时，检查 `cognitive` 与 `affective` 是否缺失。

规则：

1. **已存在的一律复用**，不调用模型、不覆盖原文。
2. **只补缺失项**。生成函数若一次返回整套维度，也只合并缺失 code，已有内容保留。
3. **两路并行**：维度解读与内涵解读同时发起，不串联等待。
4. **超时**：每路沿用现有生成函数内部约 50 秒超时；导出路由整体上限提高到 120 秒。
5. **失败不阻塞**：
   - 未配置模型：提示“AI 服务未配置”；
   - 生成失败或返回空：提示失败原因；
   - 以上情况仍继续组装文档，其余内容照常生成，不允许白屏或卡死。
6. **写回缓存**：生成成功并合并后，更新最新报告的 `result` 与 `updated_at`，按课例与用户归属限定更新范围；下次导出直接复用，避免重复计费。
7. **部分成功**：成功的一路写回并使用；失败的一路记录提示，不影响另一路。

提示信息写入文档第一章的“AI 解读补齐说明”区域，同时在页面导出完成提示中保持简洁。

### 3.3 导出入参

导出路由必须传给 docx 生成模块：

- 最新报告对象、总分、总等级、是否人工终裁；
- 课例元数据：标题、学校、班级、授课教师；
- 标准维度元信息与指标名；
- 关键事件；
- **完整座位数据**：学生座位坐标、姓名/学号、角色、布局、行列、分组信息；
- **完整互动连线**：起止座位、类型、方向、时间、说明；
- 绑定标准的档位数据（名称、分数区间、描述）与来源说明；
- 自动补齐提示；
- 导出人姓名；
- 材料原文（供旧报告证据补时间码与说话人）。

### 3.4 文件名

中文名：

```
日期_学校_班级_教师_课例_课堂分析报告_精简版或完整版_v版本_时刻.docx
```

ASCII 兜底名：

```
classroom-analysis-report_brief或full_时刻.docx
```

要求：

- 路径非法字符替换为下划线；
- 空字段跳过；
- 中文名通过 `filename*=UTF-8''...` 输出；
- 两版文件名必须能一眼区分。

### 验收标准

- 不带 variant 时仍能导出完整版。
- 报告已有全部解读时，导出不发起任何模型调用。
- 报告缺解读时，一次导出内完成补齐并写回；第二次导出不再调用模型。
- 模型不可用时，文档仍能下载，且文内有明确说明。

## 4. Word 模板改动清单

### 文书形态

- 封面独立分页；封面页不显示页码。
- 页眉显示报告名称或课例名；页脚显示“第 X 页 / 共 Y 页”。
- 每个一级章节强制新起一页；章节标题与后文同页，不出现“标题孤行”。
- 章节编号与页面口径一致：一眼看这课 / 五维拆开看 / 每条分的出处 / 课堂现场与材料。
- 摘要区显示综合等级；如经人工终裁，明确标记“人工终裁”及 AI 原始分。
- 正文宋体、标题黑体；正文 12pt、行距约 1.5 倍；表格字号小于正文。
- A4 纵向，页边距常规。
- 表格统一表头底纹、浅灰斑马纹、单元格不跨页断裂。
- 每张表有表号与表题，表号按章节连续，如“表 2-1”。

### 内容完整性

- 维度 AI 解读四段：评分依据与素材 / 为什么是这个分 / 如何解读这个分 / 如何提升。
- 认知与情感观察点明细：观察点、定义与打分归因、依据来源、得分、状态。
- 课型要点：课型名称、手册小节、识别来源（人工指定/自动识别）与置信度、要点表。
- 每个维度给出理论依据。
- 材料与数据覆盖表：材料类型、是否提供、引用证据数、缺失影响。
- 五维评分总表：维度、权重、得分、等级、待复核标记。
- 参考文献按中文排序，使用悬挂缩进。
- 缺失内容不空白：写明“未生成/未提供”，并说明如何补齐。

### 座位与互动

- 布局说明：秧田式/小组围坐式/U 型、排×列、已标注人数、分组信息。
- 图例：▲ 组织引领型、■ 协同参与型、● 观察记录型；空白格为未安排座位。
- 座位网格表：按排×列排布，每格显示姓名/学号与角色。
- 角色用浅色底纹区分，避免整格文字竖排。
- 互动清单：序号、发起方、指向、类型、方向、时间、说明。
- 无座位或无互动时给出明确提示，不生成空表。

### 附录 A 档位说明

- 优先读取课例**绑定标准**中的档位数据：档位名称、0–10 区间、0–100 区间、档位描述。
- 同一标准内各维度共用一套档位时，取任一完整维度即可。
- **任一条档位字段缺失即整体回退**系统通用五档，不要只显示部分档位。
- 回退时注明“标准档位数据缺失，以下为系统通用档位”，避免读者误读。
- 使用绑定档位时注明来源，如标准名称与版本。

### 验收标准

- 封面独立成页，首页无页码，后续页有页眉与总页数。
- 每章从新页开始，标题不会孤零零留在页尾。
- 五维总表、观察点明细、课型要点、材料覆盖、座位表、互动清单均存在且可读。
- 附录 A 显示绑定标准档位；把档位数据删掉后能自动回退并注明来源。
- Word 打开无表格错位、无大片空白、无竖排挤压。

## 5. 必须保持不变的约束

以下内容**不要动**：

1. **评分逻辑**：五维权重、指标权重、多源融合、0 分守卫、人工终裁、综合分与等级计算全部保持原样。
2. **报告数据结构**：不新增、不改名、不删除现有字段；不改变 `result` 的嵌套结构。
3. **证据呈现口径**：原文不改写；出处保留来源、时间码、说话人、解读；旧报告缺字段时沿用现有回退逻辑。
4. **页面行为**：现有报告页章节、折叠区、图表、评分编辑、人工终裁、重新生成等交互不变；不要为了导出改动页面 DOM 结构。
5. **权限与数据边界**：导出仅限课例所有者；平台总控台仍不可出现课堂内容字段。
6. **技术栈与包管理**：沿用现有 Next.js / React / docx 方案；只允许项目既定包管理器。

### 验收标准

- 改造前后同一课例的分数、等级、证据内容完全一致。
- 页面原有功能回归正常，没有因导出改动出现布局或交互异常。
- 非课例所有者无法导出。

## 6. 上线前提醒

- 确认线上环境已配置 Supabase 地址与匿名密钥；未配置时报告页与导出会返回配置错误。
- 确认 AI 模型密钥与模型名已配置；未配置时导出必须走“提示 + 仍生成文档”的降级路径。
- 确认素材/附件存储在云端可用，且上传大小限制与本地一致；不要依赖本地磁盘临时目录。
- 确认线上已关闭自助注册，账号由管理员创建或邀请。
- 确认导出路由的超时配置不低于 120 秒，避免完整版补齐解读时被平台中断。
- 确认生产构建通过，不携带本地开发缓存或本地路径。
- 不要提交任何密钥、账号、数据库连接信息到代码仓库。

## 7. 验收清单

### 页面入口

- [ ] 两个按钮文案分别为“下载精简版报告”“下载完整版报告”。

- [ ] 生成中两个按钮同时禁用；完整版有耗时提示。

### 版本内容

- [ ] 精简版含封面、一页摘要、五维总表、逐维得分、课型要点表、证据精选、课堂现场、声明与落款。

### 自动补齐

- [ ] 报告已有全部解读时，导出不发起模型调用。

- [ ] 缺内涵解读且 `essence_eval.llm_used` 为真时自动补齐。
- [ ] 补齐成功后报告已写回；第二次导出不再调用模型。
- [ ] 模型未配置或调用失败时，文档仍生成，并在文内显示提示。
- [ ] 部分成功时成功部分保留并写回，失败部分有提示。

### Word 模板

- [ ] 封面独立分页，首页无页码。
- [ ] 页眉存在，页脚显示当前页与总页数。

### 回归与上线

- [ ] 页面原有折叠、图表、终裁、重新生成功能正常。
